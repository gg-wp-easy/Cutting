# Линейный раскрой

`optimizer.py` используется всеми тремя линейными API и сервисными методами.
Для каждой доступной исходной длины строятся допустимые карты. Целочисленная
модель обеспечивает точное выполнение заказа и минимизирует суммарную длину
использованного материала, затем количество исходных заготовок. При фиксированном
заказе это минимизирует суммарный остаток. Исходные длины доступны в неограниченном
количестве: текущий API не содержит складских количеств.

Сохранена принятая в приложении модель наклонного реза: длина по длинной стороне,
чередующиеся наклонные резы, расход детали = длина − 2 × смещение + ширина пропила.
Смещение для 30° и 60° округляется вверх до миллиметра, для 45° равно толщине.
На каждую деталь учитывается один пропил, включая последнюю. Дробный пропил
сохраняется. Торцевые припуски отдельно не моделируются.

Ответ содержит прежние `maps` и `result_maps`, а также `stock_lengths` для каждой
карты и `summary`. Последний элемент карты — остаток именно её исходной заготовки.
Некорректный заказ и превышение лимитов возвращают 422 с объяснением. Частичный
заказ или решение без подтверждённой оптимальности не возвращается как успешное.
Лимиты: 100 размеров, 10000 деталей, 50000 карт, 5 секунд генерации,
20 секунд решения. Для крупных заказов потребуется отдельный алгоритм генерации колонок.

Проверки: `python -m unittest test_optimizer -v` из каталога Cutting.
Исходный requirements.txt рассчитан на Python 3.11–3.12. В окружении Python 3.13
проверки выполнены с PuLP 2.8, FastAPI 0.110, Pydantic 2.13 и pandas 2.3.

Для Windows пересоберите сервер: `pyinstaller main.spec`, затем скопируйте
`dist/main.exe` в `public/server/dist/main.exe` клиента и выполните `npm run build`.
Клиент запускает сервер дочерним процессом с рабочим каталогом userData;
история сохраняется там. Закрытие клиента завершает дерево именно этого процесса.
Windows executable необходимо собирать и проверять на Windows.
